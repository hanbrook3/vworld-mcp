# HandFun · 싱크 가사

밖에서 들려오는 노래를 마이크로 듣고, **어떤 곡인지**와 **지금 몇 초 지점인지**를 알아내
가사와 발음을 자동으로 맞춰 띄워주는 앱입니다.

- 🎤 마이크로 들리는 노래를 인식 (스피커, 라디오, 카페 음악 등)
- ⏱️ 곡뿐 아니라 **재생 위치**까지 알아내므로 중간부터 들어도 바로 싱크가 맞습니다
- 🈶 가사 밑에 **발음** 표기 — 영어·일본어를 한글로, 한국어를 로마자로
- 📱 설치형 웹앱(PWA) — 휴대폰 홈 화면에 추가하면 앱처럼 씁니다
- 📦 **외부 패키지 0개** — `npm install` 없이 `node server/index.js` 하나로 실행

<br>

## 어떻게 동작하나요

```
마이크 ──▶ 최근 5초 ──▶ 오디오 지문 ──▶ 매칭 ──▶ 곡 + 재생 위치
                        (웹 워커)      (서버)          │
                                                      ▼
                    화면 ◀── 가사·발음 하이라이트 ◀── 싱크 클럭
```

### 1. 오디오 지문 (Shazam 방식 랜드마크 해싱)

소리를 8kHz로 줄이고 스펙트로그램을 만든 뒤, 시간-주파수 평면에서 **정점(peak)** 을 뽑습니다.
정점끼리 짝지어 `(주파수1, 주파수2, 시간차)` 를 해시로 만들면, 잡음과 음량 변화에 강한
지문이 됩니다.

이 방식의 핵심은 **곡을 찾을 때 재생 위치가 덤으로 나온다**는 점입니다.
질의 지문의 각 해시가 DB의 어느 시각에 있었는지 보고 그 차이를 히스토그램에 투표하면,
같은 구간일 때만 특정 값에 표가 몰립니다. 그 봉우리 위치가 곧 재생 위치입니다.

오탐을 막기 위해 봉우리가 히스토그램 배경보다 몇 배 높은지(유의도)를 함께 봅니다.
실측상 정상 매칭은 배경 대비 8~10배, 무관한 곡은 1.4~3배로 뚜렷이 갈립니다.

### 2. 싱크 클럭

인식은 몇 초에 한 번만 하므로 그 사이는 자체 시계로 위치를 추정합니다.
새 인식 결과가 들어올 때마다

- 오차가 작으면 **부드럽게 보정** (한 번에 따라가면 화면이 튑니다)
- 오차가 크면 구간 이동/곡 변경으로 보고 **즉시 재고정**
- 최근 기준점들을 최소제곱 회귀해 **재생 속도**까지 추정 (기기 클럭 편차 흡수)

### 3. 발음 변환

| 방향 | 처리 |
|---|---|
| 한국어 → 로마자 | 연음·비음화·유음화·구개음화·격음화·경음화를 적용한 뒤 로마자로 (`학교` → `hakkyo`) |
| 한국어 → 한글 발음 | 소리 나는 대로 (`한국어` → `한구거`, `독립` → `동닙`) |
| 영어 → 한글 | 불규칙 단어 사전 + 철자 규칙(G2P) → 외래어 표기법 기반 한글 조합 (`beautiful` → `뷰티풀`) |
| 일본어 → 한글/로마자 | 어두·어중 구분, 촉음 `ㅅ` 받침, 장음 생략 (`とうきょう` → `도쿄`) |

가사 한 줄에 여러 언어가 섞여 있으면 문자 종류별로 나눠 각각 변환합니다.

## 빠른 시작

```bash
cd handfun
npm start           # http://localhost:8090
```

> **마이크는 HTTPS 또는 localhost 에서만 동작합니다.**
> 휴대폰에서 쓰려면 HTTPS로 배포하거나, 개발 중에는 `ssh -L 8090:localhost:8090` 같은
> 포트 포워딩을 쓰세요.

### 곡 등록하기

1. **내 노래 → 곡 추가**
2. 음원 파일 선택 → 브라우저에서 지문 생성
   *(음원 파일은 서버로 올라가지 않습니다. 지문만 저장됩니다.)*
3. 가사 검색으로 LRC를 가져오거나 직접 붙여넣기
4. 저장

이제 그 노래가 어디선가 들리면 **듣기 시작**만 누르면 됩니다.

### 아직 등록하지 않은 곡이라면

- **수동 시작**: 라이브러리에서 곡을 고르고 노래를 처음부터 재생
- **가사 탭하기**: 화면의 아무 줄이나 누르면 그 줄로 싱크가 맞춰집니다
- **외부 인식 서비스**: ACRCloud/AudD 키를 넣으면 등록하지 않은 곡도 인식합니다 (아래 참고)

<br>

## 설정

| 항목 | 설명 |
|---|---|
| 발음 표기 | 자동 / 한글 발음 / 로마자 / 표시 안 함 |
| 글자 크기 | 보통 / 크게 / 아주 크게 |
| 싱크 미세조정 | −2000 ~ +2000ms. 가사가 늦으면 +, 빠르면 − |
| 화면 계속 켜두기 | Wake Lock API |
| 재인식 주기 | 3~15초. 짧을수록 정확하지만 배터리를 더 씁니다 |

<br>

## 환경 변수 (전부 선택 사항)

`.env.example` 참고. 아무것도 설정하지 않아도 동작합니다.

```bash
PORT=8090
HANDFUN_DATA_DIR=/var/lib/handfun     # 기본값: handfun/data

# 매칭 민감도 (낮출수록 잘 잡히지만 오탐이 늘어납니다)
HANDFUN_MIN_VOTES=8
HANDFUN_MIN_SIGNIFICANCE=4

# 외부 음악 인식 — 내 카탈로그에 없는 곡까지 인식하고 싶을 때만
ACRCLOUD_HOST=identify-ap-southeast-1.acrcloud.com
ACRCLOUD_ACCESS_KEY=...
ACRCLOUD_ACCESS_SECRET=...
AUDD_API_TOKEN=...
```

가사 검색은 [LRCLIB](https://lrclib.net) 을 쓰며 API 키가 필요 없습니다.
ACRCloud는 `play_offset_ms`(재생 위치)를 돌려주므로 싱크에 바로 쓸 수 있고,
AudD는 곡 정보 위주라 위치를 못 받을 수 있습니다.

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/health` | 상태 |
| `GET` | `/api/config` | 기능 플래그·통계 |
| `GET` | `/api/tracks` | 카탈로그 목록 |
| `POST` | `/api/tracks` | 곡 등록 `{title, artist, durationMs, landmarks, lyrics}` |
| `GET` | `/api/tracks/:id` | 곡 상세 + 가사 |
| `PATCH` | `/api/tracks/:id` | 메타·가사 수정 |
| `DELETE` | `/api/tracks/:id` | 삭제 |
| `POST` | `/api/identify` | 인식 `{landmarks, audio?}` → `{matched, offsetMs, confidence, track}` |
| `GET` | `/api/lyrics/search?q=` | 외부 가사 검색 |
| `GET` | `/api/lyrics/get?title=&artist=` | 외부 가사 단건 조회 |

## 구조

```
handfun/
├── shared/              # 서버와 브라우저가 그대로 공유하는 순수 로직
│   ├── fft.js               radix-2 FFT
│   ├── dsp.js               리샘플링·창함수·스펙트로그램
│   ├── fingerprint.js       정점 추출 + 랜드마크 해싱
│   ├── fingerprint-index.js 역색인 + 오프셋 히스토그램 매칭
│   ├── codec.js             랜드마크 base64 압축
│   ├── lrc.js               LRC 파서 (표준/확장/평문)
│   ├── sync-clock.js        드리프트 보정 재생 클럭
│   └── pronounce/           발음 변환 (한/영/일)
├── server/              # node:http 기반 서버 (의존성 0)
│   ├── index.js             라우팅
│   ├── catalog.js           지문·가사 저장소
│   ├── lyrics.js            LRCLIB 어댑터
│   └── providers/           ACRCloud / AudD (선택)
├── public/              # PWA
│   ├── app.js               메인 컨트롤러
│   ├── mic.js               마이크 원형 버퍼
│   ├── recorder-worklet.js  AudioWorklet
│   └── fp-worker.js         지문 계산 워커
└── test/                # node:test
```

서버는 `/shared/*` 를 그대로 정적 서빙합니다. 지문 알고리즘이 브라우저와 서버에서
**같은 코드**로 돌기 때문에 둘이 어긋날 일이 없습니다.

## 테스트

```bash
npm test        # 53개 테스트, 별도 설치 불필요
```

지문 매칭 정확도는 합성 오디오로 검증합니다 — 잡음을 섞은 5초 구간으로 곡을 찾고
재생 위치를 ±100ms 안에서 맞히는지, 모르는 곡을 오탐하지 않는지 확인합니다.

브라우저 전체 경로(마이크 → 워커 → 인식 → 싱크)는 Chromium의 가짜 오디오 장치로
확인했습니다. 120초 합성 곡을 들려주면 약 6초 만에 98% 신뢰도로 인식하고,
그 뒤 22초 동안 표시 위치 오차는 0.3초 수준입니다.

## 알려진 한계

- **오디오 지문은 원본과 같은 녹음이어야** 합니다. 라이브 버전, 리메이크, 다른 마스터링은
  별개의 곡으로 취급됩니다. (Shazam 등 상용 서비스도 마찬가지입니다)
- **일본어 한자**는 사전 없이 읽을 수 없어 그대로 남습니다. 조사 `は`(wa) 같은 문법적
  예외도 반영되지 않습니다.
- **영어 발음**은 근사치입니다. 자주 쓰이는 불규칙 단어는 사전으로 처리하지만,
  사전에 없는 단어는 철자 규칙으로 추정하므로 틀릴 수 있습니다.
- **한국어 ㄴ 첨가**(`늦여름` → `는녀름`)처럼 형태소 정보가 필요한 규칙은 적용되지 않습니다.
- 마이크에서 아주 멀거나 소음이 큰 환경에서는 인식률이 떨어집니다.
  이럴 때는 가사를 눌러 수동으로 맞출 수 있습니다.

<br>

## 저작권

가사와 음원의 저작권은 각 권리자에게 있습니다. 이 앱은 사용자가 직접 보유한 음원과
가사를 개인적으로 감상·연습하는 용도로 만들어졌습니다. 가사 검색에 쓰는 LRCLIB은
이용자들이 올린 데이터를 제공하는 서비스이며, 상업적 이용 시에는 해당 서비스의 약관과
저작권 관계를 별도로 확인해야 합니다.
